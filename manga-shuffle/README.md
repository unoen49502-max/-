# 漫画シャッフル (manga-shuffle)

ネットで話題になった漫画を自動で集めて、**ジャンルが偏らないように強制ローテーションしながら**
一定時間ごとに1件ずつ表示するスライドショー。

自分で探すと結局いつも同じジャンルに戻ってしまう、という問題をソフト側で殴るためのもの。
「評判のいい順」に並べるのではなく、**見ていないジャンルを優先して差し込む**のが中心の仕組み。

---

## PC での始め方

### 1. Node.js を入れる

<https://nodejs.org/> から **LTS 版**（20 以上）をインストールする。
インストール済みか確かめるには、PowerShell / ターミナルで `node -v` を実行してバージョンが出れば OK。

### 2. このフォルダを PC に持ってくる

**ZIP でダウンロードする場合**（git を使わない一番簡単な方法）

1. ブラウザで <https://github.com/unoen49502-max/-/tree/claude/twitter-manga-auto-display-4550jq> を開く
2. 緑の **Code** ボタン → **Download ZIP**
3. ダウンロードした ZIP を右クリック →「すべて展開」
4. 展開先の中にある **`manga-shuffle` フォルダ**を、デスクトップなど好きな場所に移す

**git を使う場合**

```
git clone -b claude/twitter-manga-auto-display-4550jq https://github.com/unoen49502-max/-.git manga-shuffle-repo
cd manga-shuffle-repo/manga-shuffle
```

### 3. 起動する

**Windows** … `manga-shuffle` フォルダの中の **`start.bat` をダブルクリック**
**macOS** … **`start.command` をダブルクリック**（初回だけ右クリック →「開く」）

ブラウザが自動で開く。開かなければ <http://127.0.0.1:4187> を手で開く。
止めるときは黒い画面で `Ctrl + C`。

**コマンドから起動する場合**

`cd` の後ろは**自分のPC上の実際のパス**を書くこと（フォルダをエクスプローラで開き、
アドレスバーのパスをコピーして貼るのが確実）。

```
cd C:\Users\自分の名前\Desktop\manga-shuffle
npm start
```

> Windows の小技: エクスプローラで `manga-shuffle` フォルダを開き、
> アドレスバーに `powershell` と入力して Enter を押すと、そのフォルダで PowerShell が開く。

**`npm install` は不要**（依存パッケージなし）。

### 4. 最初にやること

```
npm run doctor
```

各フィードを実際に叩いて OK / NG を出す。RSS の提供終了や仕様変更は普通に起きるので、
うまく漫画が出てこないときはまずこれを実行する。

## 何をどう表示するか

1. **集める** — 複数のフィードから漫画関連の話題を集め、重複を落として点数をつける
2. **分類する** — タイトル・本文・タグから 21 ジャンルへ自動仕分け
3. **回す** — 「見ていないジャンル」を優先して次の1件を選ぶ
4. **出す** — 45秒（変更可）ごとに切り替え。ツイートは X の公式ウィジェットで埋め込み

画像やページの中身は**自前で保存・再配布しない**。表示は公式の埋め込みと元ページへのリンクだけで、
サムネイルも配信元から直接読み込む。

### 操作

| キー | 動作 | | キー | 動作 |
|---|---|---|---|---|
| `Space` | 一時停止 / 再開 | | `F` | お気に入り |
| `→` | 次へ | | `X` | 興味なし（以後出さない） |
| `←` | 前に戻る | | `O` | 元ページを開く |
| `R` | いま集め直す | | `S` | ジャンル統計パネル |

カーソルを画面に乗せている間は自動送りが止まる（読んでいる途中で切り替わらないように）。

ブラウザを全画面（`F11`）にしてサブモニタに置いておくと、
作業の合間に勝手に知らないジャンルが流れてくる、という使い方ができる。

## ジャンルを強制的にばらけさせる仕組み

`src/rotator.js` が中心。次の1件は以下を足し引きして選ぶ。

| 要素 | 効果 | 既定値 |
|---|---|---|
| `quality` | 評判のよさをどれだけ尊重するか | 1.0 |
| `starvation` | **見ていないジャンルを優先する強さ**（多様性の主役） | 1.6 |
| `novelty` | 一度も見たことがないジャンルへの加点 | 1.2 |
| `cooldown` | 直近に出たジャンルへの減点 | 2.0 |
| `repeatSource` / `repeatAuthor` | 同じ取得元・同じサイトが続くことへの減点 | 0.35 / 0.8 |
| `hardWindow` | **直近この件数は同じジャンルを出さない**（在庫が尽きれば自動で緩む） | 3 |
| `exploreRate` | この確率で品質を無視し「最も見ていないジャンル」から選ぶ | 0.2 |
| `temperature` | 0 に近いほど決定的、大きいほどランダム | 0.35 |

`config.json` の `rotation` で調整できる。

- **もっと知らないジャンルを浴びたい** → `starvation` と `exploreRate` を上げる（例: 2.5 / 0.35）
- **面白いものを外したくない** → `quality` を上げ、`exploreRate` を下げる
- **同じジャンルが近すぎる** → `hardWindow` を 4〜5 に

効き目はテストで固定してある（`test/rotator.test.js`）。
プールの 36% がファンタジーでも表示は 23% 程度まで落ち、
プール 2% しかない少数ジャンルは 3〜4% まで底上げされる、という挙動を検証している。

**プールを削るときもジャンル単位でラウンドロビン**する（`trimPool`）。
点数順に切り捨てると少数ジャンルが真っ先に消えて多様性が死ぬため。

## データの取得元

### 既定で有効（無料）

| ソース | 中身 |
|---|---|
| はてなブックマーク 検索RSS | 日本語圏で実際に伸びた漫画の話題。人気順・ブックマーク数つき |
| コミックナタリー / ニコニコニュース / note (#漫画) | 一般 RSS |

`config.json` の `sources.rss.feeds` に URL を足せば何でも増やせる。
**ジャンルの偏りを崩したいときは「自分が普段読まない媒体」のフィードを足すのが一番効く。**

### X (Twitter) 本体 — 既定で無効

2026年2月から X API の読み取りは従量課金が既定になり、**無料の読み取り枠は新規では取れない**
（読み取り1件あたり $0.005）。そのため既定では off。

使う場合は `config.json` に bearer token を入れる。課金が読めるよう件数上限をかけてある。

```json
"x": {
  "enabled": true,
  "bearerToken": "AAAA...",
  "maxReadsPerRun": 100,
  "maxReadsPerDay": 300,
  "minLikes": 300
}
```

`maxReadsPerDay: 300` ≒ **1日 $1.5 / 月 $45** の目安。読み取り数は日単位で数えて上限で止まる
（統計パネルに当日の読み取り数が出る）。`listId` を指定すると、自分で作った
「漫画を紹介するアカウントのリスト」のタイムラインを読む — 検索より安く濃いものが取れる。

X を無効のままでも、**はてブや RSS 経由で拾ったツイート URL は公式ウィジェットで埋め込まれる**ので
「X で話題の漫画」自体は流れてくる。

## 設定

`config.example.json` が既定値の一覧。`config.json` にコピーして必要な項目だけ書けばよい
（書いていない項目は既定値が使われる）。

| 項目 | 意味 |
|---|---|
| `display.secondsPerItem` | 1件あたりの表示秒数（UI のスライダーからも変更可） |
| `display.showTweetEmbed` | ツイートを埋め込むか。false ならリンクカード |
| `collect.intervalMinutes` | 自動で集め直す間隔 |
| `collect.poolSize` | 候補プールの上限。多いほど多様性の余地が増える |
| `collect.reshowAfterDays` | 一度見たものを再び候補に戻すまでの日数。`0` なら二度と出さない |

状態（プール・既読・お気に入り・ジャンル別の表示回数）は `data/state.json` に保存される。
`MANGA_SHUFFLE_DATA_DIR` を設定すれば保存先を、`MANGA_SHUFFLE_CONFIG` で設定ファイルの場所を変えられる。

## 構成

```
start.bat / start.command  ダブルクリック起動
bin/manga-shuffle.js       起動（サーバ + 定期収集 + ブラウザを開く）
bin/collect.js             収集の単発実行
bin/doctor.js              ソースの生存確認
src/rotator.js             ジャンル強制ローテーション ← 中心
src/genres.js              21ジャンルの辞書と分類
src/collect.js             収集とプールの間引き
src/item.js                正規化・重複排除・点数づけ
src/sources/               ソース別アダプタ（hatena / rss / x）
src/feed.js                RSS 1.0 / 2.0 / Atom パーサ（依存なし）
src/server.js              HTTP API と静的配信
public/                    スライドショー UI
```

新しいソースを足すには `src/sources/` に `{ id, label, defaults, collect() }` を書いて
`src/sources/index.js` に登録するだけ。`makeItem()` に渡せば分類とローテーションには自動で乗る。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| `node` が見つからない | Node.js 20 以上を入れる。入れた後は PowerShell を開き直す |
| ブラウザが開かない | <http://127.0.0.1:4187> を手で開く |
| ポートが使用中と出る | `config.json` の `server.port` を別の番号（例 4188）に変える |
| 漫画が出てこない | `npm run doctor` でフィードの生死を確認。NG のものは `config.json` から外す |
| 同じジャンルばかり出る | プールが小さい可能性。`npm run collect` で貯めるか、`rotation.starvation` を上げる |
